# v0.1.0 Release Notes — Draft

> **Not released.** This is a draft for the planned first public release. A
> feature belongs under "What works" only after its release gate passes.

## Summary

StudyLoop is an AuDHD-aware study toolkit: live Socratic mentoring with AI agents,
body-doubling sessions, local generation of quizzes and flashcards from your own
material, spaced repetition in the browser, and a searchable database of your AI
coding sessions across assistants.

It is versioned `0.1.0` deliberately. Under semantic versioning `0.y.z` means the
public API is not yet stable and may change in any release — which is an accurate
description of this project, not false modesty. Internal versions up to `2.5.0`
existed during development but were never published: there are no git tags, no
PyPI release, and no Homebrew formula for this package. Rather than open with a
version number implying five stable minor releases that no one could install,
the first thing anyone can actually install is `0.1.0`. The full development
history is preserved in `CHANGELOG.md` and `docs/roadmap.md`.

## Release target (not yet a shipping claim)

**Study sessions.** `studyloop study "topic" --energy 7` builds a full tmux
environment with an AI mentor and a sidebar. Mentors ask questions rather than
supply answers, and adapt to the energy level you give them: a low-energy day
gets shorter chunks and more scaffolding. Nine agent platforms are supported
(Claude Code, Codex, Kiro, Gemini, OpenCode, pi, omp, Ollama, LM Studio).

**Content pipeline.** Chunk eBooks, PDFs and Obsidian notes, then generate
quizzes, flashcards and hands-on practice tasks locally — no external notebook
service required.

**Active learning decisions.** `studyloop now` picks one useful next action from
due reviews, weak concepts, practice tasks, your energy, and the time you have.

**Flashcard review.** SM-2 spaced repetition in the browser, with a 90-day
heatmap, Pomodoro timer, optional server-side Kokoro/system voice output, and an
OpenDyslexic font toggle. The supported browser layout is tablet or laptop;
phones are explicitly out of scope for this release.

**Study plans.** In the browser, type or dictate one free-text brain dump and
let the server-owned Architect ask focused questions before it offers an exact
Markdown plan with a rendered Mermaid learning map. The learner approves,
revises, or rejects that digest-bound proposal. Existing plans can be reviewed
through the same workflow, while CLI plan commands remain structured document
management rather than a second agentic intake. At most three plans stay current.

**Session tracking.** Export sessions from every supported assistant into one
searchable SQLite database; track trends, find recurring struggle topics, and
optionally mirror each session into an Obsidian vault as Dataview-compatible
Markdown with `[[wikilink]]` backlinks.

**Live session dashboard.** Real-time activity feed over SSE, an energy-adaptive
timer, topic counters, and a live terminal rendering every supported agent as
xterm.js over a PTY WebSocket. Experimental ACP chat remains behind
`studyloop web --dev` and is not part of the v1 contract.

## Known limitations

These are stated plainly because the alternative is someone discovering them the
hard way.

- **The web app does not work offline.** There is no service worker; the
  `studyloop web` server must be reachable every time the app is opened. The
  vendored assets mean no third-party requests at runtime, which is not the same
  thing as offline support.
- **Agentic planning needs a reachable configured planning model.** The
  deterministic setup preflight proves StudyLoop's protocol, not live model
  availability. Coding harnesses used for study sessions do not supply the
  planning runtime. Run `studyloop setup --planning-base-url URL
  --planning-model MODEL` when local auto-detection finds no gateway.
- **Plan adaptation is learner-initiated in this release.** Open an existing
  plan and choose **Review with Architect**. StudyLoop does not silently rewrite
  plans in the background, and plans do not yet influence `studyloop now`.
- **A full browser reload cannot yet reattach to an in-progress planning
  conversation.** The server retains recovery artifacts, but the browser has no
  resume control yet. This must pass its release gate before v0.1.0 ships.
- **Practice tasks and topic exercises are CLI-only.** The backend and the
  MCP tools are complete and `studyloop exercise` scores them from the terminal,
  but the browser has no exercises panel yet. A Playwright journey exists as the
  specification for that work and does not pass, because the surface it drives
  does not exist.
- **End-to-end tests are not run by CI.** The `e2e` marker is excluded by
  default, so browser paths are covered only by a manual ~11-minute run and the
  nightly UAT workflow. Three tests in that suite are load-sensitive and can
  fail spuriously under load; re-run a red one in isolation before believing it.
- **`pyright` reports 47 pre-existing errors**, concentrated in three test
  files. They do not affect runtime behaviour and are tracked as their own
  cleanup task.
- **No packaged distribution.** Install is from a source checkout via
  `./scripts/install.sh`. There is no PyPI release and no publish workflow.
- **`studyloop-fake-agent` is installed on your PATH, and that is deliberate.**
  It is a scripted stand-in mentor used by the end-to-end tests. It has to be a
  real console script so the suite can exercise the genuine
  spawn → PTY → WebSocket → terminal path rather than a mock, which means it
  installs like any other command. It is registered as a selectable agent only
  when `STUDYLOOP_TEST_AGENT=1`, so it never appears in the picker; running it by
  hand just asks you scripted questions. It is not a stray binary.

## Install

```bash
git clone https://github.com/NetDevAutomate/StudyLoop studyloop
cd studyloop
./scripts/install.sh
studyloop self-test
studyloop setup
```

See `docs/first-week.md` for a day-by-day onboarding path.
