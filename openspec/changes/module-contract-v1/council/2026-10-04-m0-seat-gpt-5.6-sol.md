# Council M0 — gpt-5.6-sol

## 1. The two transport changes

**Approve both, with stronger proof and failure semantics.** PTY currently makes one non-blocking `os.write`, discards its short count, and silently returns for a missing/dead child (`packages/studyloop/src/studyloop/session/transports/pty.py:272-273,351-361`); the probe observed 1022/8192 bytes from one write and complete looped delivery (`openspec/changes/module-contract-v1/evidence/T/pty-single-write.txt:10-11`; `openspec/changes/module-contract-v1/evidence/T/pty-looped-write.txt:2-5`). Without full-write-under-lock, an 8 KiB envelope truncates and learner input, which uses the same uncoordinated method, can interleave (`packages/studyloop/src/studyloop/web/routes/session/_ws.py:192-201`). With it, backpressure can hold the lock, so the loop must handle `EAGAIN`, cancellation, child closure, and a finite write deadline. Existing `test_pty` proves whole-envelope arrival but has no concurrent sender (`packages/studyloop/tests/integration/test_module_delivery_transports.py:212-270`); add a deterministic short-write/EAGAIN test that starts a second `send_input` while the first awaits writability and asserts two contiguous blocks.

ACP currently creates an independent background prompt task for every call (`packages/studyloop/src/studyloop/session/transports/acp.py:267-288`) and `_rpc` permits multiple outstanding requests (`packages/studyloop/src/studyloop/session/transports/acp.py:447-478`). Without the lock, the red proves an envelope reaches the wire during the learner turn (`openspec/changes/module-contract-v1/evidence/T/integration-acp-no-overlap.red.txt:5-12`). With it, a hung turn blocks later prompts and queued tasks can accumulate; couple it to Q5's timeout/terminal handling. The existing overlap integration test is the correct core proof (`packages/studyloop/tests/integration/test_module_delivery_transports.py:425-465`). Reject the file-pointer fallback: it weakens “result reached mentor” to “pointer reached mentor.”

## 2. Cross-process delivery

**Choose (b), amended.** `active.current()` is only the web process singleton (`packages/studyloop/src/studyloop/session/active.py:1-18,110-117`), while the MVP executes checks only through CLI (`openspec/changes/module-contract-v1/proposal.md:310-319`); accepting (a) makes delivery unreachable in the MVP's intended CLI-check/web-mentor path. The CLI can discover the spawned web port from the cross-process state (`packages/studyloop/src/studyloop/session/orchestrator.py:244-279`), and the state directory/file are owner-only/0600 (`packages/studyloop/src/studyloop/session_state.py:93-118`). W owns the HTTP route (`openspec/changes/module-contract-v1/design.md:52-54`).

Require loopback source, a per-session capability, exact active-session and attempt binding, replay deduplication, rate limiting, strict typed-field validation, and server-side control stripping/rendering/8 KiB enforcement. Do not trust CLI-rendered text. This is a text-injection endpoint into the mentor: compromise permits forged “check” prompts, context/token exhaustion, turn disruption, and potentially adversarial module output influencing coaching despite labels. The brief's “existing session auth” is insufficient: default local web has no auth, and Basic Auth is installed only when a password is non-empty (`packages/studyloop/src/studyloop/web/app.py:218-231,275-279`); LAN mode generates a web-global password, not a session capability (`packages/studyloop/src/studyloop/cli/_web.py:96-110,138-145`). A CLI-only tmux mentor or absent server still returns learner-visible `no_active_session`.

## 3. Bracketed-paste dependence

**Track DEC 2004, but amend the fallback.** PTY already observes every child-output chunk in `_reader_loop`, so a split-sequence-aware scanner can maintain enable/disable state without changing the Protocol (`packages/studyloop/src/studyloop/session/transports/pty.py:441-449`; `packages/studyloop/src/studyloop/session/transport.py:145-151`). Probe every admitted PTY harness (Claude, Codex, Pi, Kiro) before wave 1; real support remains UNVERIFIED by the fake raw child, which merely waits for bracket bytes (`packages/studyloop/tests/integration/test_module_delivery_transports.py:152-174`). When mode is off, raw multi-line text plus CR can submit separate lines, violating one-envelope delivery. Use one printable line with output newlines escaped plus CR, or report an explicit unsupported-framing failure; the one-line fallback sacrifices readability and can hit an editor line-length limit, but does not splinter the envelope.

## 4. Auto-submit versus leave-in-editor

**Auto-submit in v1.** `send_input` exposes bytes only, no editor-state/empty-line signal (`packages/studyloop/src/studyloop/session/transport.py:145-151`), and the browser forwards input without such state (`packages/studyloop/src/studyloop/web/routes/session/_ws.py:192-201`). Prefix the pasted block with a separator newline and submit once. Bound the damage explicitly: a learner's half-draft may be submitted in the same mentor prompt, altering the response; module control bytes are stripped, the envelope is 8 KiB-bounded, and the learner just consented to that phase (`openspec/changes/module-contract-v1/proposal.md:227-239`). Leaving it unsubmitted does not satisfy delivery.

## 5. ACP `timed_out`

**120 seconds, report, never retry — but amend the implementation contract.** Today `send_input` returns after task creation and exposes neither task nor completion (`packages/studyloop/src/studyloop/session/transports/acp.py:267-288`); completion becomes `turn_end` only on the single-consumer event stream (`packages/studyloop/src/studyloop/session/transports/acp.py:290-316`; `packages/studyloop/src/studyloop/web/routes/session/_ws.py:100-105,122-152`). Therefore the ADR's claim that delivery can await this prompt is false. Add an ACP-only awaitable delivery capability while leaving `AgentSessionTransport.send_input` unchanged; learner input remains fire-and-forget. Timeout must mean “delivery outcome unknown,” cancel the ACP turn, and keep the prompt lock held until cancellation/termination is confirmed; otherwise releasing it can overlap the still-running timed-out prompt. Add a hung-fake-ACP integration test asserting one envelope, timeout visibility, no retry, and no subsequent prompt overlap.

## 6. The spec delta

**Amend the spec.** Replace the parenthetical reasons at `openspec/changes/module-contract-v1/specs/session-transports/spec.md:20-27` with the reachable outcomes: `no_active_session`, `transport_closed`, `timed_out/unknown`, validation/transport error. Make “oversize input is truncated to a valid bounded envelope” and “concurrent ACP delivery queues” explicit invariants, not runtime failures; current tests already target those properties (`packages/studyloop/tests/test_module_delivery.py:234-248`; `packages/studyloop/tests/integration/test_module_delivery_transports.py:425-465`). `serialisation_refused` is unreachable under queueing. `size_exceeded` is only unreachable after every header field is bounded: deck/task ids are now capped at 63 characters in main (`packages/studyloop/src/studyloop/content/schemas.py:269-276,313-315,339-343`), but module-id and attempt-id bounds are UNVERIFIED in the cited lane.

## 7. What the ADR gets wrong

Four findings: (1) PTY child-gone cannot be mapped after `send_input`: success and swallowed `EIO`/`EBADF`/`EPIPE` all return `None` (`packages/studyloop/src/studyloop/session/transports/pty.py:351-361`); preflight `is_running()` is TOCTOU. Make closed-write errors observable. (2) ACP has no awaitable per-prompt handle, so `timed_out` cannot be implemented as claimed (`packages/studyloop/src/studyloop/session/transports/acp.py:267-316`). These are the two claims other seats are most likely to accept too readily. (3) “existing session auth” is not session auth and is absent by default (`packages/studyloop/src/studyloop/web/app.py:218-231,275-279`). (4) the PTY integration red proves truncation/framing, not the required cross-caller lock (`packages/studyloop/tests/integration/test_module_delivery_transports.py:212-270`). F1–F4 otherwise match the cited code; F5's real-harness DEC-2004 premise remains UNVERIFIED.
