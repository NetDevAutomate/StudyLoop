# Council M1 seat glm-5 — adversarial review of drill runner (lane R)

## Findings

**WEAKNESS** `runner.py:290-295` — Output is truncated at the byte cap before redaction runs, so a secret split by the cap boundary can have part survive. The `_stream` function truncates the bytearray at `limits[name]`, then `_redact` is called on those already-truncated bytes in `run_phase`. A child that emits `AKIA...IOSFODNN7EXAMPLE` across the 64 KiB boundary could have `AKIA...IOS` survive in the kept tail. Fix: redact during streaming (detect patterns across chunk boundaries) or apply the cap after redaction when the redacted output is shorter.

**RULING** `runner.py:97` — `MINIMAL_PATH = "/usr/local/bin:/usr/bin:/bin"` excludes `/opt/homebrew/bin` where Homebrew on Apple Silicon installs `kubectl`. The brief notes this as a contract gap. A `kubeconfig-context` drill whose `scripts/check.sh` runs `kubectl` will fail unless the module author vendor-libs the binary or the learner symlinks it. Ruling: modules declare prerequisites, core executes — the runner need not add `/opt/homebrew/bin`. Document the limitation; module authors must handle cross-platform PATH differences or vendor dependencies.

**WEAKNESS** `hop.py:137-142` — The hop reads `web_port`, `practice_check_token`, and `study_session_id` from the session state file but does not verify the file's ownership or permissions before trusting its contents. The M0 arbitration states the file is written `0o600` with dir `0o700` (verified in `session_state.py:99,115`), but `session_endpoint` does not check these permissions at read time. If a malicious local user pre-created `~/.config/studyloop/session-state.json` with mode `0644` before the legitimate session, they could inject a token and port pointing to their own server. Fix: `read_session_state` should verify `STATE_FILE` is regular, owned by the current uid, and mode `0o600` (or at least not world-readable) before parsing.

**WEAKNESS** `attempt.py:204-228` — The `practice_check_events` table has an index on `(attempt_id, phase)` but no `UNIQUE` constraint. The M0 arbitration §4 item 3 specifies "replay dedup on `(attempt_id, phase)`" but this must be enforced server-side by lane W's route. The client-side DDL does not prevent duplicate rows if the same `(attempt_id, phase)` tuple is inserted twice before the server sees the second request. A network retry or race between the CLI and another process could create duplicate events. Fix: add `UNIQUE(attempt_id, phase)` to the DDL so the database rejects duplicates, or document that replay dedup is server-only and the client may write duplicates that the server later reconciles.

**EXPLOIT** `runner.py:48-50, validate_argv` — The argv length cap of 64 is enforced, but `validate_argv` does not reject NUL bytes (`\x00`) in arguments. POSIX `execve` treats the first NUL in an argument as its terminator, so an argument `"scripts/check.sh\x00;malicious"` would appear to the runner as `"scripts/check.sh"` but could be interpreted differently by a C binary that uses `strlen()` on the raw bytes. A hostile module author could craft a deck JSON with NUL-embedded arguments to bypass the shell token check. Fix: reject arguments containing `\x00` in `validate_argv` before any other check.

**Verdict:** merge after fixes

**Findings:** 4 raised (1 exploit, 2 weaknesses, 1 ruling)
