## Findings

1. **Critical — failed-create rollback can delete a foreign cluster.** Collision check and create are separate, then every create failure unconditionally deletes the name (`cluster.py:369-395,405-419`), violating `briefs/K0-cluster-provisioning.md:55-57`. Fix: never delete after an unsuccessful create without an unforgeable ownership proof; report the name instead.
2. **Critical — persisted identity/path is trusted for destructive cleanup.** `AttemptStore` accepts record `attempt_id`, `attempt_dir`, and `kubeconfig` without binding them to filename/root (`modules/attempt.py:415-425`); `handle_for` and teardown then use and unlink them (`cluster.py:168-178,423-433`). Fix: validate canonical attempt identity/path before constructing a handle; reject any noncanonical record.
3. **High — teardown failure destroys the safe recovery credential and recommends learner-default kubeconfig.** Both failure cleanups unlink the attempt kubeconfig and `_by_hand` omits `--kubeconfig` (`cluster.py:270-271,411-419,431-438`), contradicting `proposal.md:233`. Fix: retain the private kubeconfig on failed delete and print an exact safe command including its path.
4. **High — post-create exceptions can leak silently.** After create, only `ClusterError` from rewrite is caught (`cluster.py:390-401`); malformed list entries raise `AttributeError` at `cluster.py:296-305`, and `KeyboardInterrupt` also escapes before `_Disposable` exists. Fix: cleanup on every `BaseException` after successful create, preserving/reporting the original failure and cluster name.
5. **High — check errors other than timeout keep the cluster.** Close logic special-cases only `result.timed_out` (`cli/_drill.py:430-436`), while the spec says every failure (`specs/drill-runner/spec.md:86-89`). Fix: teardown on every check `ERROR` (exit ≥2, cap, timeout); retain only exit 1.
6. **High — optional phase fields can make cluster lifecycle impossible.** `phase_argv` refuses before provisioning/teardown (`cli/_drill.py:457-486`), yet no kubeconfig-target rule requires setup and cleanup. Fix: add conformance/schema enforcement or a core-only lifecycle path before K1.
7. **High — core-kind inherits unrelated secrets pre-consent.** `_kind_env` copies all of `os.environ` (`cluster.py:181-188`). Fix: explicit functional allowlist and tests proving unrelated probes are absent.
8. **Medium — “capped” kind output is accumulated unbounded.** `communicate()` buffers fully, then `_tail` truncates (`cluster.py:211-244`), missing the brief’s cap (`briefs/K0-cluster-provisioning.md:43-44`). Fix: stream with enforced byte limits and terminate on overflow.
9. **Medium — pre-consent refusals create false attempts.** Open precedes K0 preflight (`cli/_drill.py:485-542`). Fix: resolve core tools and reject no-open kubeconfig checks before `store.open`; update the characterisation test.
