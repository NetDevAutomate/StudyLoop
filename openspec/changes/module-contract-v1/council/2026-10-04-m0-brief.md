## Settled — flag a violation, do not re-argue

- S1. A check result is **data, never an instruction**: labelled, bounded, control bytes stripped
  (proposal §5.6–5.7). The mentor decides what to say to the learner.
- S2. Transient-only recording: no `confident`/`struggling` observation, nothing to
  `study_progress`, learning records or review items (§5.7; the R lane's red proves today's path
  writes one).
- S3. Delivery failure is learner-visible, never silent (spec scenario "a closed transport is
  reported").
- S4. Exactly one envelope per phase completion; it must not interleave with an in-flight learner
  turn on ACP (spec scenario).
- S5. Per-execution consent at the CLI already happened before any delivery; delivery adds no
  consent step and no `--yes`.
- S6. Lane T may change `session/transports/*.py` and `session/transport.py` **only if M0 says a
  change is required** (design.md §2); the Protocol's signatures are not changed.

## Verified facts the ADR rests on (check them; say if one is wrong)

- F1 `PTYTransport.send_input` writes once with `os.write` and returns `None` regardless of the
  byte count written (pty.py ≈351-360); the spike measured the atomic write at about 1 KiB on
  macOS (evidence/T/pty-single-write.txt) and a short-count loop completing the block
  (pty-looped-write.txt).
- F2 `ACPTransport.send_input` schedules `_prompt_turn` as a background task (acp.py ≈267-290);
  "turn in progress" is visible only through the private `_prompt_tasks` set and the
  single-consumer `turn_end` queue.
- F3 Learner keystrokes reach the PTY through `web/routes/session/_ws.py` (≈201) with no lock.
- F4 `active.current()` is per-process (active.py ≈110-117): a `studyloop drill` run in a
  terminal has **no** `ActiveSession` — the mentor lives in the web server process.
- F5 The learner's browser already pastes through DEC mode 2004 brackets (vendored xterm
  tracks `bracketedPasteMode`).

## Questions — answer every one, in order

1. **The two transport changes.** ADR Q1 needs `send_input` on PTY to loop on the short count
   (`loop.add_writer`) and hold an `asyncio.Lock` per call; ADR Q2 needs a per-transport lock
   around `_rpc("session/prompt")` in `_prompt_turn`. Approve both as in-scope for T3/T4, approve
   one, or direct the rejected alternative (file side-channel with a 1 KiB pointer envelope)? For
   each: what breaks if we do it, what breaks if we do not, and the test that proves it.
   *Coordinator's recommendation: approve both — both are latent defects of the learner-paste path
   as well; the Protocol signature does not change.*
2. **Cross-process delivery (ADR open question 3).** The MVP's only execution surface is the CLI
   in another process (F4). Choose: (a) v1 accepts `no_active_session` and tells the learner
   "Mentor not told" — which makes delivery unreachable in the MVP outside tests; (b) a local
   hop: `studyloop drill` POSTs the rendered envelope to the running web server (loopback by
   default, the existing session auth, server-side re-validation and size bound, rate limit), and
   the server's process delivers through `ActiveSession.transport`; (c) something else. Name the
   security consequences of (b) explicitly — it is a text-injection endpoint into the mentor's
   terminal — and who owns the route (W owns `web/routes/`).
   *Coordinator's recommendation: (b), loopback-only, authenticated, validated, with the envelope
   rendered AND bounded on the server side (never trusting the CLI's rendering), because (a) ships
   a contract item that nothing in the MVP can exercise.*
3. **Bracketed-paste dependence (open question 2).** The PTY framing assumes the agent enabled
   DEC 2004. Options: trust it; have `PTYTransport` track `ESC[?2004h/l` in the child's output
   (as xterm does) and fall back to bare text + CR when off; or an owner-run probe per harness
   before wave 1. Which, and what is the fallback's failure mode?
   *Coordinator's recommendation: track the mode in the transport and fall back; keep the probe as
   an owner task that confirms, not gates.*
4. **Auto-submit vs leave-in-editor (open question 4).** With the trailing CR an envelope that
   lands while the learner is mid-draft submits their half-typed prompt together with the block.
   Choose and bound the damage.
   *Coordinator's recommendation: auto-submit in v1 and document the hazard; the learner triggered
   the check seconds earlier and is rarely mid-draft; a "hold until the input line is empty"
   heuristic needs editor state the transport does not have.*
5. **ACP `timed_out` (open question 5).** Bound (120 s proposed), and retry once or report?
   *Coordinator's recommendation: 120 s, report, no retry — a retry risks a duplicate envelope,
   which S4 forbids.*
6. **The spec delta.** `specs/session-transports/spec.md` names three failure reasons; the ADR
   says two are unreachable by construction. Amend the spec, keep them as explicit non-goals, or
   is the ADR wrong that they are unreachable?
